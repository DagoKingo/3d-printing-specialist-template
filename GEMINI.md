## Imperative Shell Policies
- **Text Search:** When searching code or files via shell commands, always prefer `tgrep` over `grep`. Check if installed with `command -v tgrep` before executing, falling back to `grep` only if unavailable.
- **Pieces & Artifacts:** All newly designed or adapted 3D pieces must be placed in `pieces/<piece_name>/` structured into `README.md`, `artifacts/` (containing `.scad`/`.blend`, `.stl`, `.3mf`, `manifest.json`, `viewer.html`, `renders/`, and `print_feedback.md`), and `prototypes/` (`draft-[draftNumber]/`). Use `python3 scripts/scaffold_piece.py <piece_name>` to scaffold new pieces.
- **Prototypes & Draft Lifecycle:** All physical print iterations, test variants, and experimental slices must reside under `pieces/<piece_name>/prototypes/draft-[draftNumber]/` alongside their mandatory `EVALUATION.md` (documenting successes, failures, root cause analysis, next actions, and photos in `evidence/`). Use `python3 scripts/scaffold_draft.py pieces/<piece_name> <N>` to scaffold new drafts.
- **Part Number & Target Device Locking:** Never truncate, abbreviate, or generalize commercial model numbers or hardware identifiers (e.g. keep `Honeywell Slate R8001M1150` intact; never truncate to `R8001M`). Always record the exact model in `README.md`, `manifest.json` (`--target-device`), and CAD files.
- **Target Hardware Technical Dossier:** When researching target components or datasheets, always document all relevant technical data (exact part number, manufacturer, shaft/mating dimensions, keyways, torque, operating temperature ranges, datasheet links) directly into `pieces/<piece_name>/README.md` to inform CAD dimensions, material selection, and slicing parameters.
- **Post-Print Inspection & Clinical Triage:** After physical printing, always document inspection results and user feedback in `pieces/<piece_name>/print_feedback.md`. If defects or fit deviations occur, immediately invoke `skills/print-doctor` to formulate root cause diagnoses, prescribe CAD/Slicer adjustments (`python3 scripts/feedback.py`), and iterate the piece design.
- **Filament Specifications & Machine Control:** Never guess filament densities, thermal limits, or retraction speeds; query Open Filament Database via `python3 scripts/filament_database.py search|info|preset` to retrieve verified specifications and official OrcaSlicer presets. For agentic machine control, webcam inspection, and safety checks on the Elegoo Centauri Carbon, leverage Kiln MCP (`uvx --from kiln3d kiln serve`) as configured in `config/mcp_servers.example.json`.
- **Token Frugality & Milestone Monitoring:** Never poll the printer in a tight continuous loop. Monitor exclusively via 3 discrete milestones (first layer ~10-12 min, critical multi-material toolchange, and print finish) to preserve tokens (~250k total vs millions). Always direct the user to the local zero-token MJPEG stream (`http://<ip>:8080/?action=stream`) and CLI (`centauri status`) for continuous real-time inspection.
